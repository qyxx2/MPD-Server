# Task 8/9 手机 Web 真人验收方法

日期：2026-10-09；UI合同同步：2026-10-10。状态：本文是方法而非验收记录；当前交付与仍待真人项读取active Batch Plan/最新acceptance，不能由本文判断页面尚未交付或已通过。

## 1. 定位与范围

手机浏览器是主要使用和真人验收环境。Ubuntu 的 Firefox、Chromium 用于 AI 预检、定位和必要兼容检查，不要求开发桌面专用布局或逐 Batch 做双桌面浏览器全量验收。PWA 安装、独立窗口、Service Worker、冷离线壳及更新验收延期，不阻塞 Task 8 手机 Web 交付或 Task 9 启动；以后有需要再实施和验收，不标记已完成。

产品行为仍以现有 business/architecture Specs 为准；视觉、通知、背景、共享壳及导航仅以 [全局 UI 合同](../specs/2026-10-03-web-pwa-visual-design.md) WEB-UI-* 为准，本文只规定操作方法，不复制尺寸/颜色合同。本文件只拥有真人验收操作、交付格式和反馈流程。Task 8 必验场景由其 Batch Plan 指定；Task 9 以后在自己的 Contract Audit/Batch Plan 中选择适用场景，不在这里预拆 Batch 或确定尚未冻结的业务语义。

## 2. 最小准备与局域网交付

不新建验收场景控制台、报告系统、独立 UI 应用、公开故障注入 API，也不为验收引入新框架或 Docker。准备纳入现有 W1–W3 支持范围，不新增 W0：W1 核对 native 启动/代理条件，W2 完成已有状态机制的自动验证，W3 首次交付手机可访问的实际 Player。

每次交付页面前，AI 必须完成：

1. 使用现有 `.venv/bin/python` 和前端计划范围内的 Node 依赖；显式注入 MockMPD，使用独立验收 SQLite 和自建媒体/歌词资源。不得仅设置 `MPD_MODE=mock` 就假定入口已切换 Mock；当前 main 未消费该开关。真实 MPD/NAS 联调另需明确授权。
2. 优先复用既有 app、Services、Repositories、fixtures 与 API；必要时仅增加小型本机启动/数据准备脚本。临时数据与运行日志置于 ignored 或临时目录，不覆盖已有数据库或真实音乐；重置只限明确归属本次验收的数据。
3. 前端监听 LAN 可达地址，后端可保持 loopback，通过前端 `/api` 代理统一 REST/WS。本机代理不能依赖 Docker 主机名 `server`；开发/构建预览都需核对实际代理目标。不得要求手机直接访问第二个后端端口或写死 MPD 地址。
4. 检查实际监听端口及本机页面/API/WS，识别与手机同网段的实际 LAN IP；排除 loopback、容器和 VPN 地址。交付 `http://<实际局域网IP>:<实际端口>/`，例如端口可用时使用 5173；地址和端口不能只给占位符。`0.0.0.0` 是监听地址，不是手机访问地址。
5. 提供产品页面、构建/代码标识、当前场景和简短验收卡；保持进程运行，记录实际重启/停止方法。未提交代码不能只用 HEAD 标识版本，要附验收轮次或构建时间以区分修改。
6. 手机首次打开确认连通性。若不可达，先检查同一 LAN、Wi-Fi 客户端隔离、监听和防火墙；环境阻塞单列，不能判作 UI 不通过，也不擅自更改系统防火墙或路由。

普通手机显示/触摸验收使用局域网 HTTP 即可，不为此搭建 HTTPS、隧道或域名。手机上已经加载页面的断线/恢复可测试；全新离线启动不要求有应用壳。HTTP LAN 下不能执行的安装/SW 项记录 DEFERRED，不要求用户修改浏览器安全设置。

本文件不维护实时地址或进程状态，不能据此断言应用尚未启动。以后各 Batch 交付时必须填写当时核验的真实地址。本机预检通过不能代替手机实际可达确认。

## 3. 场景准备方式

常见场景用少量固定测试数据和既有 API/Service 准备：正常曲、长中文/英文标题、缺封面、未知元数据/时长、LRC、plain/no lyrics、空集合及可用/不可用媒体。只在当前 Batch 需要时加入对应数据。

用户不用数据库、终端或开发者工具操作。需要换场景时由 AI 用本机脚本/API 准备，说明“当前场景已切换，请刷新/继续”，用户继续操作同一个实际产品页面。Task 8 选曲由夹具准备，不提前实现 Task 9 Library/SongRow。

普通断线优先在已加载手机页面上关闭 Wi-Fi/移动数据，再恢复同一 LAN；AI 保持服务运行。复杂时序（WS 单独断开但 HTTP 成功、旧 GET 倒灌、key 重用、seek 中途切歌、迟到资源）优先使用现有可注入 transport/clock 自动测试。仅在当前缺陷复现确有需要时做小型本地夹具，不为每个自动场景建设手机控制按钮。

Mock 验收不证明声音、DAC 或真实 MPD 精度。现有 Mock elapsed 不随墙钟自动推进；W4/W5 如需连续进度/歌词演示，由最小验收夹具提供明确标记的时间推进和实际状态更新，不改产品 store、不增加前端播放权威，不把模拟自然完成当设备证明。

## 4. 手机通用基准与验收卡

手机首次记录型号、系统、浏览器名称/版本；后续仅在变化时重记。主验使用用户实际手机和常用浏览器，不要求采购设备或覆盖完整浏览器矩阵。

| 编号 | 操作/条件 | 可见通过基准 |
|---|---|---|
| M01 | 手机竖屏打开当前页面，滚动查看 | 主次层级清楚；普通内容无横向溢出；主操作不被浏览器工具栏/页面固定区遮住 |
| M02 | 点按当前 Batch 的按钮、菜单、切换器 | 目标易点，不误触邻项；选中/禁用/pending/失败可辨；重复点按不造成重复业务副作用 |
| M03 | 当前页面输入文字，打开/关闭软键盘 | 输入、结果、关闭/确认操作可达；收起键盘后布局恢复；底部导航在 Task 9 范围才验 |
| M04 | 显示长中文/连续字符/emoji标题、缺图、未知字段；放大文字 | 遵守WEB-UI-STYLE/BG/SHELL/NOTIFY：保留结构槽位、不推挤控件；完整值可访问；unknown不伪造为零；亮/杂乱封面可读，缺图fallback稳定 |
| M05 | 已加载页面断网，再恢复 LAN | 最后事实明显 stale/read-only；业务写操作不可用；新 initial snapshot 后恢复；不补发断线期间操作 |
| M06 | 切后台或锁屏后返回 | 不继续展示虚假的计时/歌词推进；按实际连接和样本恢复；不产生重复 listener/业务请求 |
| M07 | 当前 Batch 涉及动画、歌词/菜单 | reduced-motion 与无 blur fallback 保持可用；必要时由 AI 在 Ubuntu 预检，不要求手机安装调试工具 |

M01/M02 为每个可见交互 Batch 必验；其余按影响选择，未涉及可写 N/A + 原因。手机真机结果是主要证据；Ubuntu 缩窄窗口仅辅助检查约 320–430 CSS px、长文本、文字缩放及 fallback，不作为手机触摸通过证明。宽屏保持手机内容的合理限宽即可，不增加多栏桌面设计、桌面导航或额外宽屏视觉验收。

标准不要求复刻旧概念图；当前Player与WEB-UI-*是保护基线。不得按每Batch反馈自行改变共享尺寸/通知位置；用户要求更改统一规则时先更新唯一Visual Spec并检查影响，各页继承。涉及新功能或后端合同须先说明范围，不把视觉反馈当作功能授权。

## 5. Task 9 功能验收映射（非 Batch 拆分）

未来 Task 9 Batch Plan 必须为其新增页面/交互指定下面适用卡；每张卡在实施前补充按已冻结合同确定的具体步骤和预期。禁止只写“手工看看”。

| 编号 | 实际页面/操作 | 验收重点 |
|---|---|---|
| T9-H01 | 四项导航、Player默认入口、Library内部详情/返回/刷新；同一视口记录切换前后位置 | WEB-UI-SHELL/NAV/BG：只换中间内容；app bar/导航几何与背景身份连续，无闪动/重复底部预算/重复连接；Player比例及冻结歌词回归 |
| T9-H02 | Queue 分区、历史展开/重置、触摸排序 | Now Playing/Played/Up Next 清楚；MANUAL/AUTOPLAY 可辨；仅允许项可排序；不误操作相同 URI 的不同项 |
| T9-H03 | Queue Play Next/删除/清空/保存 Playlist | 操作目标明确；成功/失败符合服务端事实；刷新或返回后保持一致 |
| T9-H04 | 各页面 SongRow 同一播放菜单及独立星标 | 播放动作一致；点星标不播放；Play Now 按后续冻结原子入口验收 |
| T9-H05 | Library collection/详情、Play All/Shuffle All | 动作对应所选 collection；长文本、空/加载/不可用状态可辨 |
| T9-H06 | Playlist 创建/重命名/加歌/重复拒绝/排序/移除/删除 | 手机输入与触摸流畅；结果跨视图同步；拒绝/失败不伪装成功 |
| T9-H07 | Favorites 及各页面收藏星标 | 进入/返回或换视图后状态一致；取消收藏生效；失败反馈明确 |
| T9-H08 | 六类字段搜索、快速改词、清空、无结果 | 软键盘不遮操作；迟到结果不覆盖新查询；空/无结果/不可用可辨 |
| T9-H09 | Settings → About及已有NAS_DAC控制入口 | 真实API事实、unknown/错误原因进顶部详情；输出事实/请求分离；HTTP串流仍不可用，不添加Task10等未授权设置 |
| T9-H10 | 当前页面断线/恢复、后台返回、跨页pending/多个异常、点击顶部详情及原retry/read | 继承M05/M06和WEB-UI-NOTIFY：唯一顶部通知/详情、无其它提示文字；原intent/key与read-only门禁保持，未解决异常不被覆盖；资源恢复不串曲、不跳动 |

Task 9 的测试数据按需要包括：历史/当前/手动/AutoPlay Queue 项、重复 URI occurrence、空 Playlist、长名称、不可用歌曲。内部 key、revision、请求顺序由 AI 的自动测试/日志证明，不要求用户手工读网络记录。

## 6. 交付、反馈与复验

自动 Gate 通过后，AI 给出当前 Batch 的真实 URL 和少量可执行编号项，标记 HUMAN PENDING，等待用户手机反馈。必要真人项通过前不关闭该 Batch 或自动推进下一 Batch；可以继续定位和准备本 Batch 内工作。

反馈可以只写：`W4-H02 不通过：松手后滑块先退回；希望同步期间保留清楚的等待反馈。其他项通过。` 截图/录屏可选，不强制；用户无需复制长表。

AI 按同场景复现→判断 owner/范围→最小修复→精确失败测试及要求回归→更新实际页面→给出新轮次和需复验编号的顺序处理。状态/时序缺陷须留下必要关系测试；纯低影响视觉调整不强制增加镜像测试。修改若影响其他已通过项，列出一起复验。服务重启/IP 改变时重新核对地址并告知用户，不让旧页面缓存或旧进程冒充新版本。

产品缺陷和本 Batch 内视觉调整留在当前 Batch；超出范围的新功能或合同变化单列。用户明确放宽某项时记录变更及影响，不能由 AI 自动跳过失败项。用户结论才是 HUMAN PASSED 的依据，AI 预检/截图和 automated GREEN 不替代。
