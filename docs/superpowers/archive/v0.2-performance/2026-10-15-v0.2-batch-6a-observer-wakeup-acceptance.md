## 实现与接口决议

- `StateObserver.request_observation()` 为同步、无 I/O 的合并信号；使用 Event 与递增需求代次。保留原单一采样任务与工作完成后的 1 秒周期兜底。
- 一轮开始时捕获需求代次。该轮任一阶段收到新请求，结束后立即补一轮；旧轮不能消费新请求。需求检查和清除 Event 之间没有 await；空闲等待同时等周期或请求，先到者触发下一轮。每次等待的两个辅助任务只负责等待，不采样，均在结束/取消时清理，不按点击创建采样任务。
- `PlaybackService.set_observation_request(callback | None)` 由 `main.lifespan` 装配并在关闭 Observer 前解除。现有原子操作边界比较观察 generation 与不可变 binding 的前后值；既覆盖暂停/切歌等状态变化，也覆盖 append 等仅绑定发生变化的路径。同一外层事务只登记一次唤醒；普通 observe/get 不登记，避免反馈循环。
- **最小接口调整决议：** 使用现有 `on_transaction_visible` 同步钩子，在 SQLite 成功 commit 后发信号，回调只执行 Event.set；回滚清理登记但不唤醒。这里没有交接或公开确认样本，不属于 B6-B。采用此钩子而非排在异步通知之后的 commit 回调，是为了避免 domain publisher 的阻塞/提交后取消延迟或丢弃唤醒。Observer 只能在该同步边界交还事件循环后运行，原 DB 锁仍按既有流程释放；没有引入网络 I/O 或等待观察完成。
- 信号只请求真实读取，成功/失败、current/token、generation 与完整样本接纳继续由既有观察逻辑处理。回滚后的外部副作用仍遵循原失效/UNKNOWN 规则，没有把“已唤醒”当成确认成功。
