## 2. 适用模式与合同优先级（WEB-LANDSCAPE-001）

两种布局共用一个 AppShell、AppBar、路由、session、realtime 生命周期、业务 API、通知投影及全局背景。

- 手机/iPad 纵屏沿用现有单列布局、信息层级、交互和媒体切换。共享 AppBar 的明确增量见 §6，除此之外不重新设计纵屏。
- 横屏以 iPad 书页比例为第一基准，2420x1668(注意要考虑到横纵屏状态顶部都始终有浏览器状态栏占用) 最重要；桌面16:9为第二基准。手机横屏是同一系统的窄尺寸情况，不建立设备专用结构。
- 采用前序讨论中的能力门槛：CSS viewport `width >= 900px` 且 `orientation: landscape` 进入双栏；其余保留单列。900px 是本次补全的执行起点，须测试899/900/901px；不足900px的手机横屏使用既有单列退化，不宣称所有手机横屏都能容纳双栏。
- 不按 UA/iPad/Desktop 名称判断。桌面窄窗、竖向窗口也按相同规则；正方形视口按 portrait 单列处理。CSS 与组件模式判断必须一致。

本文在双栏内替代全局 UI 合同 §5 的28rem单列/底部64px预算，以及 §7 首项“正在播放”的表现。§6 的共享 AppBar 改动适用于横竖屏，并覆盖旧20px图标及普通信息常驻表现；最近5项、恢复动作和领域安全合同继续生效。其余视觉、播放、Queue、Library、输出合同继承原文。

## 3. 主舞台与水平尺寸（WEB-LANDSCAPE-GEOMETRY-001）

连续的主舞台内排列 `Player → gap → Right Content`，两者组成一个视觉组居中。45/55只说明空间倾向，不是CSS列宽或各自居中的规则；不使用24%/74%中心点。Player不能贴左边缘或变成小卡片；右侧不能在无限剩余空间里居中。左右区域不加大卡片、独立背景板或中央竖线。

以下按默认根字号16px、CSS像素计算；实施时以rem语义和实际可用空间处理字号缩放。clamp表达式为设计计算，不要求原样复制成CSS。

| 参数 | 常规目标 |
|---|---|
| 主舞台最大宽度 | 90rem / 1440px |
| 基础水平外围留白 M | clamp(28px, 3.2vw, 48px)，左右各自再与 safe-area 取较大值 |
| Player宽度 P | clamp(340px, 36vw, 400px)，高度足够时封面使用此宽度 |
| 右侧布局宽度 R | clamp(420px, 46vw, 560px) |
| 两者间距 G | clamp(32px, 3.5vw, 48px)，紧张时先缩到24px |
| 右侧实际内容限宽 | Lyrics/Settings 480px；Queue/Library 560px |
| Artwork | 正方形，最大400px，圆角10–12px，无厚重边框 |

确定算法：

1. 设左右安全留白为 L/U，可用舞台宽 `S = min(1440, W - L - U)`；在安全区域内居中舞台。
2. 计算 P、R、G。若总宽大于 S，先减G到24px，再将基础外围留白减到16px（safe-area仍是下限），重新计算S；仍不足则优先保持P，将R减至320px，最后才减P及封面。触摸目标和基础字号不参与缩小。
3. 总布局组宽 `C = P + G + R`，整体在S内居中。右侧实际宽 `Q = min(R, 当前页内容限宽)`，**从右栏起点排布**，内部文字可按既有规则对齐；不再用 `(R-Q)/2` 将整个窄内容右移。因此切换页面时Player保持同一位置，右侧内容中心由 `Player右边缘 + G + Q/2` 得到。
4. G按Player可见内容边界到右侧内容容器边界测量，不按单行歌词字形边缘测量。常规目标32–48px，不能长期大于64px；高度降级导致封面变小时也检查实际间隔。若缩小整个Player宽度，重新计算组宽及居中，不保留空的大左栏。
5. 多出的宽度留在整个内容组外围，不拉大G，不无限放大封面、歌词字体、列表行或设置卡片。布局目标受高度预算约束，不能以固定宽度表掩盖纵向溢出。

无safe-area、默认字号、宽度未受高度限制时的计算参考（四舍五入到1px，允许2px舍入差）：

| Viewport | 舞台S | Player P | G | 右栏R | 组宽C | Player左边缘距viewport |
|---|---:|---:|---:|---:|---:|---:|
| 1024×768 | 958 | 369 | 36 | 471 | 876 | 74 |
| 1194×834 | 1118 | 400 | 42 | 549 | 991 | 101 |
| 1366×1024 | 1279 | 400 | 48 | 560 | 1008 | 179 |
| 1920×1080 | 1440 | 400 | 48 | 560 | 1008 | 456 |

此表是水平预算，不是已验收截图。Lyrics/Settings实际Q可能小于R，但其左边界保持上述G，不另外居中增加空洞。

## 4. 高度、滚动与短屏（WEB-LANDSCAPE-HEIGHT-001）

AppBar内容高44px，顶部安全区单独计入；AppBar后主舞台呼吸8px。Dock高60px，底部间距 `clamp(12px, 1.5vh, 16px) + safe-area-inset-bottom`，内容到Dock顶部另留12px。纵向预算只由壳计算一次。

设可用动态viewport高度H、顶部安全区T、底部安全区B、Dock底部普通间距D，则：

`舞台可用高度 = H - T - 44 - 8 - 60 - D - B - 12`

令F为Player标题、艺术家、进度/时间、控制及当前可见次要信息和全部内部间距的**实际高度预算**，封面边长 `A = min(P, 400, 舞台可用高度 - F)`。Player视觉组在舞台内垂直居中；右侧内容使用同一舞台可用高度，长内容在右侧内部滚动。Player、AppBar和Dock不跟随右侧滚动。

原聊天的 `clamp(200px, 100dvh - 390px, 400px)`只作粗略草案，**不作为实现公式**：它既未表达safe-area和实际文字预算，也不能保证短屏不溢出。正常iPad横屏争取360–400px，1194×834优先400px；1024×768的369px目标要求F不超过约263px，1194×834的400px目标要求F不超过约297px（均无安全区）。实现须测量F再核对，不能直接声称满足。

空间不足时依次缩减左右gap/外围留白，封面按剩余高度缩小，收紧内部空隙，再压缩/隐藏专辑、源格式、DAC等次要信息；不缩基础字号。歌曲名、艺术家、进度/时间、播放控制及可用操作保持可达，文字缺失/变长不推动框架；保留固定行数预算及长文本访问能力。普通紧凑模式封面约200px为软目标，不能用min-height硬撑而盖住控制。

极端高度、放大字号或键盘使“封面200px + 核心控制”无法容纳时，先允许封面进一步缩小；仍无法容纳时退回现有可滚动单列布局。这是可达性补全例外，不能通过裁切/隐藏核心控制维持双栏；须在验收记录触发条件、实际尺寸及原因。正常双栏Player不设置独立滚动。优先用CSS可用空间预算，确需测量时避免反复切换模式的布局振荡。

右侧各页只保留必要的纵向滚动所有者；保留标签条横滑、Queue拖动边缘滚动和歌词跟随，避免壳与子页双重纵向滚动。浮层、菜单保持现有可访问性，通知详情在内容层及拖动浮层上方。软键盘下输入/保存/取消可达，键盘关闭后恢复布局，不能重建session或触发播放。

## 5. 页面、导航与状态连续性（WEB-LANDSCAPE-NAV-001）

| 路由 | 双栏内容 | 单列内容 |
|---|---|---|
| `/` | 左侧Player封面 + 右侧Lyrics | 现有Player及封面/歌词切换 |
| `/queue` | Player + Queue | 现有Queue |
| `/library`及所有现有子路由 | Player + 对应Library/搜索/收藏/歌单/详情 | 对应现有页面 |
| `/settings` | Player + Settings | 现有Settings |

横屏Dock四项顺序为**歌词、Queue、音乐库、设置**，第一项仍指向 `/`，无desktop-only路由。Library子路由选中音乐库，前进/后退、刷新、深链接按既有路由处理。旋转不修改URL，不强制写入纵屏mediaMode；返回纵屏恢复原选择。左侧封面在横屏恒显示，不提供一个与右侧歌词重复的“封面/歌词”开关；右侧Lyrics不显示“返回封面”入口。

Player展示可以拆组件，但只能有一套事实、时钟、mutation owner、session与realtime连接。不要同时挂两份隐藏Player/Lyrics来实现响应式。保留歌曲链接、收藏、播放控制、seek、锁定/read-only、原key重试和HTTP确认后只重读的语义；旋转及导航不得触发播放写请求。保护路由子页已有滚动/筛选/草稿状态，不为布局无条件重置它们。

Lyrics复用解析、跟随、选择、cue/seek、错误处理及现有字号；Queue保持单列、行高和独立可触摸操作；Library保持当前默认歌曲、排序、标签条和单一内容层级；Settings保持窄内容及现有可用功能。不得借本次横屏新增设置项、输出模式、浏览器音频或后端API。

## 6. 共享AppBar状态增量（WEB-LANDSCAPE-APPBAR-001）

横竖屏使用同一AppBar及状态投影。去除MPD SERVER等非状态文字，中央保留唯一入口；内容高约44px（安全区不包含在内），可见图标约24px，点击范围至少44×44px。图标消失时保留几何槽位，不能改变AppBar高度。

| 优先级 | 状态 | 图形与持续时间 |
|---|---|---|
| 1 | warning、failed、unknown、stale/disconnected及现有需处理异常 | 橙色警告图标，持续至解除；并发busy不能覆盖警告图形 |
| 2 | pending、syncing | 蓝色/cyan spinner，持续到结束；reduced-motion静态忙碌表现 |
| 3 | 普通成功/信息 | 蓝色信息图标，状态变化后5秒消隐 |
| 4 | 无活动 | 无可见图标 |

5秒按稳定活动id与实际状态变化序号计算；轮询刷新同一状态、切页、旋转均不重置。高优先级遮住普通信息时计时仍继续，解除后只显示尚未到期的信息。计时器属于共享状态展示生命周期，不为每页复制；卸载清理，使用fake timers验证。

消隐只影响中心图标，不删除最近活动/未解决事项/恢复上下文，不清空最近5项。详情已打开时不因5秒到期强关；关闭后若无活跃状态则隐藏。后续新活动可重新打开同一详情，不新增历史入口或第二通知系统。焦点位于入口时保留其至焦点离开以免焦点丢失，并记录此可访问性例外。

继续使用统一详情浮层、最近5项、全部未解决事项汇总、原有read/retry权限、Escape/焦点返回与live region。不能把异常吞在最近5项之外，也不新增Toast、Banner、页面通知区。状态色使用统一语义token；仅对本状态表现校准橙色，保留非颜色识别线索。

## 7. Dock、背景与视觉（WEB-LANDSCAPE-STYLE-001）

横屏Dock相对**整个viewport**水平居中，图标+短标签，宽 `min(320px, viewport宽 - 两侧安全留白)`、高约60px；各项点击范围至少44px，底部距离和避让预算按§4。不能相对Player或右栏居中，不能变成整宽底栏。遇左右不对称safe-area仍优先viewport中心，实际触及不安全区域才约束到安全区域并记录。

Dock圆角约16px、半透明、blur、细边框与柔和阴影；无backdrop-filter时使用可读半透明/实色退化。它是常驻布局中唯一强调悬浮容器的结构；既有菜单、通知详情等临时浮层可继续使用保证可读性的底色/边框。

AppBar、舞台左右内容和Dock后方使用同一专辑模糊背景；沿用当前28px blur与0.8深色蒙版为起点，保护当前已确认资源身份、迟到拒绝、无图/读取失败及stale退化。跨页/旋转不重复建立背景请求，不拿列表选中项代替当前专辑。对比度沿用全局UI合同：普通文字4.5:1、大字及必要非文本3:1；若需调节，统一背景token校准，不逐页叠遮罩。

沿用深蓝黑、近白正文、cyan重点色和系统字体。增加宽度主要增加外围呼吸空间，不放大歌词/标题/列表到桌面巨型尺寸；不用关闭缩放来保证布局。Artwork为1:1微圆角，既有图片资源/加载机制保持。
