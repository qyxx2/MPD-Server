- 本文：上述事实在 Web 上的表达、共享壳、视觉尺度、通知位置和四项导航；主 Plan、Batch Plan 不得用旧视觉描述覆盖本文。

- 当前代码、测试与用户反馈：核对实现和验收是否真实存在。archive 仅保留当时证据，不作为新实现指令。

## 2. 当前事实与 Player 保护基线（WEB-UI-BASE-001）

2026-10-10 核对当前分支 `feature/task-8-web-player` 的工作区源码、W5 acceptance 和已有 A05/A06 截图；有未提交修改，不能把 HEAD 当作完整页面版本。本轮未启动服务、未操作播放、未重新执行自动/真人验收。截图是历史辅助证据，不是本轮真机测量。

| 项目 | 当前存在的基线 | 新合同尚待落实的差距 |
|---|---|---|
| Shell | 单 AppShell 拥有 realtime 生命周期；Player 单路由；header 仍在 Player 内 | 持久全局 app bar/四项导航与跨页生命周期 |
| 比例 | 手机竖向单列、内容限宽 28rem；动态视口高度、伸缩媒体区；底部预留 4rem + safe-area | 把预留转为唯一导航预算，跨页固定框架 |
| 顶部状态 | app bar 中心固定图标；同步 spinner；点击异常详情及原 retry/read；浮层不入流 | 目前仅播放操作归顶部，连接标签、文件/读取异常、歌词说明、需选曲提示等尚未全部归一 |
| 背景 | 深蓝黑默认径向氛围背景 | 当前专辑高斯模糊 + 薄蒙版的唯一全局背景尚未实现 |
| Player | 方形封面/同区透明歌词；标题/艺术家/源格式、DAC事实、进度、三按钮；无 Stop UI/Output卡片 | 保持这些成果，仅做必要的壳/背景/通知接入 |
| 进度 | W1–W4 产物存在；A04 歌词有 HUMAN PASSED/FROZEN 记录 | W5-A06 比例/状态仍 HUMAN PENDING，W6/Task 9 未验收；本轮不晋升 Gate |

后续必须保留：媒体区和歌词交互、3秒恢复跟随/选择不误 seek、封面点击进入歌词/右上角返回、共享展示时钟、进度与按钮能力、无 Stop UI、无 Output 底部卡片、DAC 确认事实与源格式分离。长期歌词行为仍以 Library Spec §3.1 为准，不在本文重定义解析/计时。

已完成的行为不得为“统一风格”重做或改值。接入时允许将通知说明迁入 app bar、将 header/底部预算迁入共享壳，以及增加背景资源展示；通知接线涉及歌词组件时仅迁移提示，不更改已冻结的歌词正文样式、解析、跟随/选择/cue 行为。必须先记录当前基线，再做最小接入及指定回归。历史通过项不因本文重开；触及对应合同仍须回归。新规则不能冒充当前实现已满足。

## 3. 视觉语言与对比度（WEB-UI-STYLE-001）

沿用 Player 的深蓝黑、轻薄透明、近白正文、冷蓝/cyan 强调、柔和深度和系统无衬线字体。媒体/内容与 app bar、导航自然过渡；不得用生硬分割线、独立厚卡片或不同底色将三者切成三块。既有控件/进度内部细线可保留，不作为新页面分区模板。列表与设置用留白、字重及轻量选择态分组，菜单/详情浮层可有足够实色底以保证可读性。

基线 tokens 来自 `web/src/styles/tokens.css`：

| 角色 | 基线值 |
|---|---|
| 默认背景 / 氛围 | `#080d18` / `#142438` |
| 主 / 次 / muted 文字 | `#f3f7fc` / `#bdcadb` / `#9cacc2` |
| accent / focus | `#82d5f8` / `#a4e4ff` |
| success / warning / error | `#9be4bb` / `#f3cc91` / `#ffb6b4` |
| glass / overlay | `rgba(21,31,47,.85)` / `#1b293c` |
| 字体 | Inter、ui-sans-serif、系统字体；无网络字体依赖 |
| 圆角层级 | `.6rem / 1.1rem / 1.7rem`；不要求增加卡片 |

使用统一语义 tokens，不让各页散落另一套值。颜色值是当前基线，不证明覆在任意专辑图上都可读。必要验收阈值：普通文本对比度至少 4.5:1，大文字至少 3:1，操作图标/焦点等必要非文本至少 3:1；成功/异常/禁用不能仅靠颜色。字体随系统缩放，禁止通过关闭缩放保证布局。

Player 标题沿用 `clamp(1.5rem,6vw,2rem)`、行高1.3；艺术家行高1.5；源格式/时间约 `.8rem`、compact标签约 `.75rem`。新页面标题/正文采用同一角色体系，不能每页扩大标题导致框架变化。通知详情采用紧凑正文约 `.8–.875rem`，随用户缩放；按钮文字同样紧凑，点击范围仍至少44px；长说明在浮层内部滚动，不能变成超大标题。

## 4. 唯一全局背景（WEB-UI-BG-001）

所有页面共用一个由持久 shell 持有的全视口背景：**Player 已确认的当前专辑图片，高斯模糊 + 轻薄深色蒙版**。页面内容不另铺专辑图、渐变大卡片或页级背景。沿用 Task 5 artwork API 与既有 Player 表示/资源身份保护，不从 Queue、列表选中项、最后业务歌曲猜当前封面。

- 背景图采用 cover、适度 overscan，模糊边缘不能漏白/黑缝；覆盖 app bar、内容及导航。前景封面仍清晰、contain、正方形，不随背景模糊。
- 浏览 Queue/Library/Settings 或打开详情不更换背景、不卸载或重新请求同一背景；只有已确认当前歌曲/专辑或合法资源版本改变才更新。断线/stale时可保留最后接受的当前专辑背景，与顶部read-only/过期说明配合；身份明确失效或从未确认时使用当前默认背景，不能拿最后业务歌曲伪装当前背景。
- 缺图、404、无当前歌曲或图片读取/解码失败采用当前默认径向背景；真正读取失败在 app bar 表达。正常“没有封面”不是确定错误，缺失与失败在顶部详情中可区分。
- 读取/解码期间保留稳定的默认底层；图片只在完成解码且身份仍有效时显示，切歌迟到图片不得倒灌。布局不随 loading/成功/失败改变。既有已确认 handoff 展示不能被当成新确认身份。
- blur 半径和蒙版透明度属于后续实施参数，先以薄蒙版满足对比度；对极亮/杂乱封面允许统一调节蒙版保证第3节阈值，不能为每页再造遮罩。不在本文凭截图编造已验收数值。
- 背景层不参加布局、不拦截触摸、不随内容滚动；无 blur 支持时使用默认背景，保持文字可读。切歌可短暂淡入，禁闪白、缩放或影响布局；reduced-motion 使用静态替换。

## 5. 持久框架、比例与稳定性（WEB-UI-SHELL-001）

固定组合仍由唯一持久 AppShell 承载。手机/iPad 竖向保持现有单列主体；横向进入统一的双栏舞台。不得按 iPhone、iPad、桌面分别创建三套布局，也不得复制 AppShell、realtime、背景或通知生命周期。

- **竖向基线**：手机竖屏与 iPad 竖屏继续使用当前单列 Player/页面结构。现有 `28rem` 内容限宽、动态视口、底部触摸预算等只作为竖向合同，不再解释为所有宽屏的限制。
- **横向触发**：`orientation: landscape` 且 CSS viewport width `>= 900px` 时进入横屏双栏模式。设备型号不参与判断。低于该宽度的极窄横屏继续使用现有单列作为可用性 fallback，不为手机单独维护另一套横屏设计。
- **横向主基准**：iPad 4:3/近书页比例是第一设计基准；桌面 16:9 是第二基准。横屏规则以连续弹性尺寸表达，不针对某一具体设备写死像素。
- **横向舞台**：AppBar 下方为一个连续、居中的主内容舞台；舞台不是卡片，不加边框、阴影或独立底色。舞台最大宽度 `90rem`（1440px），水平边距使用 `clamp(1.75rem, 3.2vw, 3rem)`（约28–48px）。超宽桌面增加外围留白，而不是继续放大主要内容。
- **名义左右比例**：Player 区约45%、右侧页面区约55%，这是空间分配方向而非内容定位硬规则。实际内容采用下面的弹性宽度和整体居中组，以避免 Player 过小或 Player 与右侧内容产生大空洞。
- **横向内容组**：Player 与右侧页面组成一个整体内容组，整体在主舞台中居中，不分别把两个区域独立数学居中。推荐实现 token：Player rail `clamp(21.25rem, 36vw, 25rem)`（340–400px）；Right rail `clamp(26.25rem, 46vw, 35rem)`（420–560px）；两者间距 `clamp(1.5rem, 3.5vw, 3rem)`（24–48px）。内容组自然宽度不足主舞台时保留两侧留白；不得用拉大 Player↔Right gap 消化剩余宽度。
- **Player 优先级**：Player 是横向主要视觉主体之一，在舞台允许范围内优先保持较大的实际尺寸。空间不足时先压缩 Player 与 Right 的间距，再减少外围舞台留白/重新计算舞台宽度；不得为了满足45/55数学比例主动缩小 Player，也不得把 Player 与右侧页面推得很远。
- **Right 内容定位**：Right rail 紧跟在 Player rail 后面。页面内容可以比 Right rail 更窄，但其水平定位以“与 Player 保持合理间距、同时在右侧区域形成稳定视觉中心”为原则，而不是强制居中于剩余全部视口。实际 Player↔可见内容间距目标约32–48px，绝对不应因窄内容的居中计算长期超过64px；超过时应向 Player 侧回收空白。
- **页面内容宽度**：Lyrics 文本列目标最大约 `30rem`（480px）；Queue/Library 主列表最大约 `35rem`（560px）；Settings 目标最大约 `30rem`（480px）。这些是内容最大宽度，不是字号放大依据。页面必须在各自 Right rail 内协调留白，不能贴屏幕边缘。
- **横向垂直预算**：AppBar 内容行固定约44px；AppBar 不因路由标题、通知数量或长文案增高。AppBar 后只保留约8px主舞台上缘呼吸空间。Dock 视觉高度目标60px，底部与 Dock 之间约12–16px，并额外计入 safe-area；主舞台为 Dock 预留完整避让区，但背景连续铺到底部。
- **Dock**：横向导航是相对整个 viewport 水平居中的紧凑悬浮 Dock，而不是整宽底栏。目标宽度 `min(20rem, calc(100vw - 2 * horizontal-gutter))`，通常不超过320px；目标高度约60px，触摸项至少44px。图标+短标签统一四项，Dock 使用轻薄半透明/blur、细边框和柔和阴影，圆角约1rem；除此之外不使用大面积边框分割。
- **横向导航映射**：横向 Dock 四项为“歌词 / Queue / 音乐库 / 设置”。“正在播放”不再作为 Dock 项，因为 Player 已常驻左侧；第一项仍使用 `/` 路由，进入 `/` 时右侧显示 Lyrics。竖向 Dock 保持“正在播放 / Queue / 音乐库 / 设置”。
- **横向 `/` 行为**：路由仍为 `/`，不增加 desktop-only 路由。横向 `/` = 左侧固定 Artwork Player + 右侧 Lyrics；`/queue`、`/library...`、`/settings` 分别显示对应右侧页面。旋转不会因为布局模式自动改写路由。
- **横向 Player**：复用现有纵向 Player 的信息层级 `Artwork → 歌曲身份 → 源格式/DAC事实 → 进度 → 播放控制`，但重新计算尺寸和间距。Player 内容在左 rail 内偏向内容组中心，而不是贴左屏幕边缘。Artwork 维持1:1，目标最大400px；横向主基准下优先做大。
- **Artwork 尺寸与高度降级**：推荐基线 `clamp(12.5rem, calc(100dvh - 24.375rem), 25rem)`，即约200–400px，并同时受 Player rail 宽度限制。正常 iPad 横屏通常落在360–400px；高度不足时先缩 Artwork，再压缩模块间距，最后隐藏源格式/DAC、专辑等次要信息；歌曲名、艺术家、进度/时间、播放控制优先保留。基础字号不得通过整体缩小来解决高度问题。
- **Artwork 形状**：保持1:1，但采用微圆角，约 `0.6rem–0.75rem`（约10–12px）。不新增厚重外框或独立卡片；优先复用现有圆角 token。
- **Player 不滚动**：正常及短高度横向模式下 Player 不作为独立滚动容器。高度不足按上一条降级；不得让播放控制被 Dock 覆盖。右侧 Lyrics/Queue/Library/Settings 承担自己的内容滚动。
- **Lyrics 横向表达**：复用现有 Lyrics 解析、3秒恢复跟随、cue seek、错误语义和文本样式。横向时 Lyrics 独立位于 Right rail，不再与左侧 Player 共用 Artwork/Lyrics 切换；左侧始终显示 Artwork。横向不显示“显示封面”这种已经没有意义的内部切换入口。旋回竖向后恢复此前的 portrait mediaMode，不把横向固定 Artwork 状态写回竖向状态。
- **Queue/Library/Settings**：继续复用已有页面和业务组件，不因为 iPad/Desktop 而把列表强行变成多栏网格或显著放大字号。Queue 以连续单列为主；Library 允许合理利用 Right rail 宽度；Settings 保持较窄的阅读宽度。已有功能控件的边框仅作为控件自身 affordance，不作为页面分区模板。
- **全局背景**：沿用现有全视口专辑图背景，当前实现基线为 `blur(28px)` + `var(--artwork-shade)`（当前 `.8`）。背景跨 AppBar、Player、Right rail、Dock 后方连续存在；不得为左右区域增加独立背景板。
- **安全区与稳定性**：横向舞台/Player/Right rail/Dock 均正确计入 `env(safe-area-inset-*)`。状态变化、路由切换、背景加载、歌词/列表加载不得改变 AppBar、主舞台或 Dock 几何。Dock 只悬浮覆盖其自身避让区，不遮挡可操作内容。

### 5.1 横向参考几何（非设备硬编码）

以下仅用于实现前的比例校准，不构成设备特判或真人通过证据。按 `edge-gutter = clamp(28px, 3.2vw, 48px)`、舞台最大1440px、Player `clamp(340px,36vw,400px)`、Right `clamp(420px,46vw,560px)`、gap `clamp(24px,3.5vw,48px)` 计算：

| 参考 viewport | 舞台约宽 | Player | gap | Right rail | 内容组余量（舞台内） |
|---|---:|---:|---:|---:|---:|
| 1024×768 | 958px | 369px | 36px | 471px | 约82px（两侧合计） |
| 1194×834 | 1118px | 400px | 42px | 549px | 约127px（两侧合计） |
| 1366×1024 | 1279px | 400px | 48px | 560px | 约271px（两侧合计） |
| 1920×1080 | 1440px | 400px | 48px | 560px | 432px（两侧合计） |

这些结果体现的不是“把空白填满”，而是**Player 与 Right 保持接近、内容组整体居中、超出的宽度转化为外围留白**。尤其在 iPad 4:3 主基准下，Player 不贴左边缘，Right 也不贴右边缘；两者之间只保留合理 gap。

### 5.2 AppBar 全局统一状态合同

AppBar 只保留一个共享组件和一套状态语义，横竖屏均适用。`MPD SERVER`、last-business 等非状态内容不再占用 AppBar；歌曲身份、格式、DAC事实继续留在 Player。

| 状态 | 中心表达 | 持续规则 |
|---|---|---|
| 无活动 | 无可见图标，保留固定中心槽位 | 不占用布局，不闪动 |
| pending / syncing | 蓝色/cyan 循环 spinner | 持续到该事项结束或转入异常 |
| warning / failed / unknown / stale / disconnected | 橙色警告图标 | 持续到问题真正解除；优先于 spinner/info |
| 普通成功 / 已同步 / 一般信息 | 蓝色信息图标 | 仅显示5秒；5秒后隐藏 |

中心状态图标可见尺寸约24px，触摸目标至少44×44px；AppBar 内容行约44px。状态优先级为异常 > pending/syncing > 5秒普通信息。新活动到来可重置5秒计时，但不能因为轮询刷新同一事项而反复延长。详情浮层仍最多展示最近5项；关闭浮层不清除事项。

AppBar 在手机竖屏、iPad 竖屏、手机横屏、iPad 横屏和桌面使用同一状态投影、同一计时/优先级/恢复语义；只允许通过响应式参数调整图标/padding等视觉细节，不允许维护两套状态逻辑。

### 5.3 横向视觉禁止项

- 不使用左右大卡片、中央竖分割线、整宽底栏或页级背景板表达双栏边界。
- 不因为“桌面”而使用巨型标题、巨型封面、超宽列表或额外工具栏。
- 不把 Player 缩成小型 Now Playing 卡片；左侧必须保持完整的现有 Player 信息层级和主要视觉重量。
- 不把右侧内容强制定位到剩余55%区域的几何中心，导致 Player 与内容之间出现大空白。
- 不用固定 `45vw/55vw` 或固定设备像素代替上述弹性约束。
- 不在横向复制一套 Player、Lyrics、AppBar、Background 或导航组件；优先复用现有资源并只增加布局容器/响应式表达。

## 6. 顶部唯一活动合同（WEB-UI-NOTIFY-001，2026-10-16统一）

所有活动及目前已实现提示统一投影到 AppBar 中心唯一状态入口；本节的横竖屏状态语义完全一致。此前“黄色感叹号长期表达异常”和“蓝色感叹号可持续常驻”的旧显示规则由本次合同取代；历史 acceptance 只保留为历史证据，不视为新规则已验收。

唯一入口是 AppBar 固定中心图标与一个详情浮层。播放/seek/handoff、资源加载、同步中/已同步、扫描、收藏/歌单/地址保存、操作未完成/结果未知/失败、连接/stale/read-only、封面/歌词原因等全部接入同一活动投影。不另建toast/banner、页面提示区、曲目同步图标或日志页面。

| 状态 | 中心表达 |
|---|---|
| 有需处理的 warning / failed / unknown / stale / disconnected | 橙色警告图标；优先于其它活动，即使该项不在最近5项 |
| 无上述异常但有 pending / syncing | 蓝色/cyan 循环 spinner |
| 无待处理异常/进度但有近期成功或一般信息 | 蓝色信息图标；仅显示5秒，随后自动隐藏 |
| 无活动 | 几何槽保留，图标消失 |

中心图标可见尺寸约24px，固定触摸目标至少44×44px；AppBar 内容行约44px。中心槽位固定，不因图标显示/隐藏、详情长度、路由或设备方向改变高度/位置。异常优先级高于处理中，处理中高于5秒普通信息。普通信息的5秒计时只由实际状态变化触发；轮询同一事项不能持续续期。

所有来源投影成活动项：稳定id、来源/简短动作名、关联资源、状态、状态变化序号、短说明、既有允许的retry/read。一个事项更新原项，不同时展示operation/statusFeedback/notices的重复文案。仅实际状态变化更新最近次序；按最近状态变化倒序展示至多5项（统一限额，包含播放专用条目和通用通知）。成功结果可留在本会话最近活动中直到被新项挤出，最多缓存5项已完成记录；跨epoch不带回旧成功，重连状态不伪造新操作成功。

展示裁剪不删除未完成操作及恢复上下文。中心图标汇总全部当前未解决事项；详情可显示不算活动项的汇总“另有N项未完成，完整记录见日志”，不增加第6项/分页/无限历史。关闭浮层只关闭展示，不清除事项。

恢复动作保持原合同：pending仅展示进度；unknown重试原intent/payload/key；HTTP已确认后读取失败只重读；断线禁止mutation。普通活动不新增恢复按钮。业务结果仍由API/observation确认，前端活动不是第二套业务权威。

业务内容仍留原处：歌曲身份、格式、DAC事实、进度、availability、收藏选中态、空集合占位及歌词正文；它们不是第二通知区。

## 7. 四项导航与页面映射（WEB-UI-NAV-001）

顶级导航始终只有四项，横竖屏共享同一四项导航组件和路由集合；仅标签/选中语义根据布局模式调整。

| 布局 | 第一项 | 第二项 | 第三项 | 第四项 |
|---|---|---|---|---|
| 竖向 | 正在播放 → `/` | Queue → `/queue` | 音乐库 → `/library` | 设置 → `/settings` |
| 横向 | 歌词 → `/` | Queue → `/queue` | 音乐库 → `/library` | 设置 → `/settings` |

竖向第一项仍表示完整 Player 页面；横向第一项表示右侧 Lyrics，而 Player 已永久占据左侧，因此不再重复提供“正在播放”导航入口。路由本身不因方向改变而增加 desktop-only path。

横向 `/` 的固定结构为：左侧常驻 Artwork Player + 右侧 Lyrics。`/queue`、`/library...`、`/settings` 分别将对应页面放入右侧；左侧 Player 始终保持。切换右侧页面只更换右侧内容，不卸载共享 Player/AppShell/realtime/background/notice 生命周期。

横向 Lyrics 复用现有 LyricsStage 的解析、跟随、cue seek 和错误语义，但不再显示内部“显示封面”切换按钮；左侧 Player 始终显示 Artwork。横向模式不改写竖向 `mediaMode`，旋回竖向时恢复此前的封面/歌词选择状态。

Queue行提供独立更多操作按钮（待播移为下一首/移到队尾及删除；current/Played仅删除），正文整行点击播放保持；清空待播确认和保存名称输入为本地操作浮层，不承载第二套通知。保存/拒绝/恢复仍归顶部唯一通知，触摸入口至少44px。

Queue待播排序由独立手柄长按激活；允许自然手指漂移。拖动浮层跟随指针，原列表保持稳定，插入标记不改变行高；靠近内容边缘时滚动，松手以实际落点判定。current/Played及列表外为无效落点，取消不得误提交上一次目标。浮层处于共享通知层下方，不拦截点击，不写入服务端事实。

图标为主，每项有可访问名称、选中态与足够触摸区域；横向 Dock 使用图标+短标签的紧凑形式，视觉高度统一，不因页面切换改变。Library 内搜索/歌单/收藏及详情沿用同一 app bar/navigation/background，不成为第五项导航；返回/刷新/深链接的顶级选中归属一致。

NAS_DAC enable/disable 的 UI 入口归设置，复用既有 Output API/事实分离及自动测试；Player 只保留原 DAC confirmed 摘要。CLIENT_STREAM/HTTP 首期尚未支持，不提供可点击的假切换、更不增加浏览器播放。

## 8. 工作顺序与所有权（WEB-UI-DELIVERY-001）

本次横屏方案只冻结设计/尺寸/响应式合同，不创建/修改产品代码、测试、依赖、数据库、构建产物，不启动服务，也不把设计规则当作已验收结果。

后续实际实现必须按以下顺序推进，仍由对应 Batch Plan 决定具体文件与 Gate，不在本文预拆 Batch：

1. **Shared Shell / AppBar**：先把唯一 AppBar、44px状态行、5秒普通信息/持续异常/处理中 spinner 语义统一到现有 Shell；移除 AppBar 的 `MPD SERVER`/last-business 展示依赖。先保证竖向 Player 不回归。
2. **Background / responsive stage**：保持现有专辑图模糊背景单例，加入横向媒体查询和主舞台尺寸约束；验证竖向 `28rem` 单列行为完全不受影响。
3. **Dock / route mapping**：将横向导航切换为紧凑悬浮 Dock，横向第一项显示“歌词”但仍指向 `/`；建立左右舞台与现有路由内容的稳定挂载关系。
4. **Landscape Player**：复用现有 Player 事实、控件、Artwork、进度和收藏能力，只做横向尺寸/间距/圆角适配；按高度降级顺序保护核心播放控制，不把 Player 缩成小卡片。
5. **Right rail**：先接 Lyrics，再接 Queue、Library、Settings；各页共享 Right rail 的尺寸/滚动/边距基础，但允许页面自己的最大内容宽度。不得为了统一宽度而把 Settings/歌词强行铺满。
6. **Responsive / rotation audit**：至少核对 1024×768、1194×834、1366×1024、1920×1080 等参考几何，并补充实际设备 viewport；检查横竖旋转、safe-area、系统字号、极短横屏、reduced-motion、无 blur 支持。
7. **Acceptance**：Contract Matrix、Relationship / Invariant Gate 与真人验收必须区分 Implementation、automated、phone HUMAN、desktop 辅助等证据；本设计文档的尺寸表不是验收证据。
