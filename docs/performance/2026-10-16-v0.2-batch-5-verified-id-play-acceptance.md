## 发送前的连接边界

独立审查发现只替换发送函数还不足以保留重连安全：若在完整验证后、发送前断线，旧 Adapter 会自动重连并发送旧 ID；新 daemon 可能已把该 ID 用于其它 URI。新增确定性回归先观察到 `playid 18` 被发送，再收到 UNKNOWN，不能把事后拒绝当作没有错误控制。

为此内部 `PlayerPort.queue_play` 增加可选关键字参数 `expected_connection_epoch`，VerifiedPlayerPort 保留原 runtime capability gate 并转交此参数，MockMPD 实现同一拒绝语义，Executor 总是传入固定 intent baseline 的 epoch。旧的无参数调用仍可使用；HTTP API 不变。

Adapter 在持有通信锁的 `queue_play` 中将 epoch 传至真实发送协程 `_execute`，在 `_ensure_connected` 和 `wait_for` 调度之后、`writer.write` 之前比较，中间没有 await。若 epoch 不同，抛出 PlayerUnavailable，原 Executor 将操作封入 UNKNOWN 并失效绑定，不发送旧 ID、不回退 URI、不重新播放。此检查不增加正常路径网络命令。

这只约束本服务可见的 connection epoch；完整样本与控制之间仍不是跨客户端 MPD 物理事务，保留原外部竞争及事后完整确认边界。不扩展为其它命令的传输重构。

## 可执行验收与读取预算

`server/tests/invariants/test_verified_id_play.py` 使用真实 SQLite、RecoveryJournal、VerifiedPlayerPort、MPDAdapter 与 localhost TCP 模拟器，不连接生产服务。

| 情况 | 证明 |
|---|---|
| 8/400 首，已有唯一/重复 URI 映射 | 精确目标 ID，1 次 playid；2 份完整样本对应 2 次 playlistinfo，无独立 URI 搜索 |
| 8/400 首，新增唯一/重复 URI occurrence | 使用已确认 add receipt 的 ID，1 次 addid + 1 次 playid；3 份完整样本对应 3 次 playlistinfo |
| terminal replay | 返回原完整结果，零网络读取/控制，无业务或 History 变更 |
| 目标预先删除、执行入口重连 | 完整核验拒绝，零播放命令，无成功 receipt/event |
| playid 响应丢失、ACK 后重连 | 不提交成功；retry UNKNOWN，零盲重发 |
| 完整验证后目标删除 | MPD 拒绝精确旧 ID，记录 rejected；不搜索同 URI 替代项，retry 不控制 |
| 验证后断线、已重连、真实发送任务启动时断线 | 旧 ID 即使指向其它 URI，也在发送前拒绝；retry UNKNOWN，无业务提交或成功通知 |

服务整链路复用原 B4 的 8/400 首 Next/song/Played 预算和 occurrence/History 断言，仅调整 B5 明确减少的独立查询：

| 操作 | 完整 sample（不变） | playlistinfo：基线→B5 | 控制命令（不变） |
|---|---:|---:|---|
| Next | 8 | 9→8 | playid×1、deleteid×1 |
| song 立即播放 | 8 | 9→9 | addid×1、moveid×1、playid×1、deleteid×1 |
| Played occurrence | 10 | 12→11 | addid×1、playid×1、moveid×1、deleteid×1 |

song 整链路本来已在 queue 同步阶段用 ID 播放，因此该路径没有额外 B5 降幅；move 内部独立读取仍保留。不把“适用路径少一次查询”写成所有操作都少读，完整样本也没有减少。
