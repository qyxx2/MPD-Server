## 原读取链、消费者与有效性边界

`LibraryRepository.get_song` 查询 Song 主记录，再 `_song_from_row` 查询 artwork（有 album 时）、artists、album artists、genres、tags、album 并构建完整 Song。无 album 是每次6条 SELECT，有 album 是7条。

| 操作 / 阶段 | B1 读取 | B2 读取 / 消费字段 |
| --- | --- | --- |
| next：`_next_available_pending` | 全部 Pending 逐项完整 Song；删除不可用项 | fresh 批量 Pending；song_id/availability 分类，occurrence 原顺序保留；同步分类完成后执行既有删除 |
| next / song：`_verify_user_queue_baseline` | 操作前 current + 全 Pending，逐项完整 Song | fresh 批量；song_id/file_uri；缺失仍沿用该 occurrence 的已知 journal URI；完整 MPD 核验不变 |
| next / song：`_desired_song_uris` | 当前完整 Song，Pending `_require_available_song` | fresh 批量；三字段；current 必须存在但可不可用，Pending 必须 AVAILABLE；URI 由 occurrence 顺序排列 |
| 普通 song Play Now：保留项校验 | 全部 Pending 逐项 `_require_available_song` | fresh 批量 Pending；缺失/不可用立即原错误拒绝，零 MPD 控制 |
| 目标选择、History 当前资格等既有读取 | 单目标完整 Song | 保留既有接口；正常预算中仅2次完整 Song，避免扩展修改目标/History/观察模型 |

三字段依据：song_id 将数据库返回映射到业务 occurrence；file_uri 用于 preflight/执行 URI；availability_status 用于 Pending 拒绝/next 跳过。没有 title、artwork 或 artists 等消费者。`PlaybackSong` 是 Repository 内部 frozen dataclass，未修改公开 Song/API DTO。

Repository 每次调用通过原 `run_transaction` 重新 SELECT，无连接/事务/请求/TTL缓存。输入去重仅限 song_id，返回 dict 不依赖数据库顺序；Queue occurrence、MPD ID 和相对顺序完全独立。空输入零查询；缺失 ID 不返回；每块最多 `min(900, connection.getlimit(SQLITE_LIMIT_VARIABLE_NUMBER))`，同一 root 内同步完成所有块，保持查询切面。

批量返回后的字段验证/映射同步完成，无 await、无 Library 写；next 先完成同步分类再执行原 Queue 删除，后续 target 校验、preflight、sync 均重新读取。生产 QueueManager.delete 不写 Library。这里不存在“同事务等于缓存仍有效”的推断：同 root 的下一调用也重新查询。preflight 修复、AutoPlay refill 后重新获取所需集合；MPD 控制或其它 await 后不携旧 projection 回到下一阶段。失败、取消、rollback、retry 没有状态需要清除或继承；固定 intent/receipt 仍是执行事实，URI变化造成既有 identity conflict，而非缓存旧 URI 掩盖冲突。

## 合同 proof 与回归义务

| 合同 / 权威 | 新proof与既有回归 | 必须保持 |
| --- | --- | --- |
| PB-NEXT-UNAVAILABLE / Library §9 | pending freshness、scan、cancel后retry；PlaybackService/Library availability | AVAILABLE保留顺序；MISSING/UNREADABLE/不存在跳过；下一目标fresh |

| PB-RECOVERY-RETRY / TX | root写后fresh、Repository rollback、fixed intent URI conflict、cancel；D6 execution/recovery、事务/idempotency | SQLite回滚不撤MPD；旧snapshot不泄漏；UNKNOWN不盲重发；terminal replay无控制 |
