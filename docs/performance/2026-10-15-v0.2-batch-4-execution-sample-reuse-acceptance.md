设计只复用**本次正常 preflight 的完整实际样本作为新 prepare/queue intent 的规划输入**。
执行器首次完整采样和 `_verify` 保持原位置、原比较与原错误处理；它们才授权发送命令。
旧样本不被当作后续外部状态的证明。不是直接跳过 executor 验证，不增加轻量 guard，
不改变 Port、adapter、receipt、观察、History 或通知接口。

三个方案的取舍：

1. 直接把 baseline/final 当作后续实际确认：拒绝。外部 MPD 不受 DB/TCP 本地锁冻结。
2. status guard + 旧完整队列：本批不选。需要额外界定全部字段、缺失、fallback 与版本合同。
3. 复用规划输入，保留原命令前完整核验：采用。只删除一次 planner-only 读取，
   若 preflight 后发生持续漂移，原 executor 在首条 sent 前 fail closed。

生命周期：`_verify_user_queue_baseline` 仅在新操作、完整映射与 current 正常匹配时返回样本；
其余分支返回 None。`_prepare_play` / `_sync_player_queue` 各自在没有固定 intent 时使用局部变量。
无实例字段、全局缓存、TTL、跨请求 handle；repair 后仍重新采样；已有 intent、
confirmed prefix、UNKNOWN、rollback retry 与 terminal replay 不取得此候选。
样本和嵌套 status/entries 由现有 ExecutionSample 冻结。

preflight 之后依旧存在 Library/Queue 读取 await、意图规划和自然推进窗口。
它们不被假定安全或被冻结；executor 的新完整样本会与规划输入比较 epoch、partition、
version、完整 ID/URI/顺序、current ID/position/state、single/consume/random/repeat。
持续漂移在控制前拒绝。原来可由较晚 planner 读到并重新规划的变化，现在可能保守拒绝。
elapsed 可推进，volume 不授权 occurrence；error 行为保持原合同。
采样间 current 离开后返回等不可见瞬变仍属 Spec §8.9 的限制，本批不宣称可识别。
末次完整外部验证到 send 的代码完全不变，没有新增 await/guard/CPU planning。

`_expected` 只是预测比较对象；没有把它或 ACK 冒充实际 sample。

`execution_samples` / `sync_sample` / `receipt.sample` 都是对应已发生阶段的历史证据。

不重新消费 preflight、不重发控制。rollback 不撤销 MPD；进程重启不继承 runtime 成功证明。

## 两个 handoff 的资格与失败边界

| 消费点 | 资格/归属/生命周期 | 失效与处理 |
|---|---|---|
| preflight→prepare planner（Next/Played/previous等已有选择入口） | 同次 Service 调用的局部返回值；完整 preflight 当前正常匹配；新 prepare intent；只用于规划，不用于发命令授权 | 已有 intent、修复/重试无返回候选，沿用原完整 baseline/retry read；候选之后的外部漂移由原 executor 完整读拒绝 |
| preflight→queue planner（普通 song、append/no-command等直接sync入口） | 同次局部返回值；新 queue intent；没有跨 prepare 控制继承；完整映射仍经原 planner 检查 | 同上；若先经过 prepare，preflight已消费为None，sync保留独立完整读与B1 handoff检查 |

没有新 handle、缓存/TTL、额外 guard、跨阶段消费或 Port 能力；不支持/缺字段/torn/
读超时/重连仍走原完整采样与既有 fail-closed。失效不尝试新 key、按 URI 找回未知 add、
降低 observer/runner 频率或改变 generation/sequence。新旧本地业务状态的共享事务只用于
现有业务串行化，不作为 MPD 未变化的依据。跨await窗口仍由后置实际完整核验覆盖。
